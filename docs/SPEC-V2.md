# SPEC-V2 · Fusion Office 总规格（唯一构建依据）

## 1. 目的（为什么做）
把一支**自主运行的智能体队伍**放进一间**看得懂的办公室**：运营者不读日志、不读 JSON，进门看一眼就知道谁在干活、干得合不合规矩、钱（先是虚拟钱）的账对不对。V1 是数据看板；V2 是玻璃房办公室。
- 主角是 grokbot 的 meme 币纸面交易台（原样基座）：它的监督/审计/彩排逻辑是全站的灵魂。
- 新增一支「股票交易员」队伍：A股/港股/美股**模拟交易**，同样受监督、同样的工单记账方式。
- 其余信息（行情、定投赛跑、机械蜘蛛、财经观测台）是这栋楼里的分室，为办公室提供情报与校验。

## 2. 形式（长什么样）
- **基座**：Vazolini/grokbot-jev-dashboard 的 index.html 原样保留其布局、动画、组件与数据通道（办公室插画、8 机器人格、底部三面板、20 秒轮询 data 分支 state.json）。不重画皮。
- **视觉系统**：以 grokbot token 为全站语言：玫红底 #e04aa6+6px 网格、黑卡 #111116、等宽字体、人格色（粉/绿/红/黄/青/橙）。分室一律沿用。
- **结构**：顶栏加分室导航（办公室 / 交易台 / 行情 / 赛跑 / 蜘蛛 / 财经观测台）+ 中英切换。办公室是默认主场。
- **语言**：界面全量中英双语（默认中文）；数据自带的葡语日志经模板翻译层显示为当前语言（见 §5）。

## 3. 方法（怎么推进，依次）
1. 研读原仓（已完成，STUDY.md）→ 2. 本规格 → 3. 后端（serve.py：FinSight 接口复用 + 办公室数据代理 + 模拟交易 API）→ 4. 办公室基座双语化与翻译层 → 5. 交易台 → 6. 其余分室与财经观测台 → 7. 真机截图与回归验收 → 8. 推送到独立仓 `ZHANGFA88/fusion-office-stock-simulator`（2026-10-17 已由维护者确认公开发布；与其他项目仓库使用不同名称）。上游 grokbot 未声明 LICENSE，不据此推断额外授权或再许可。

## 4. 数据契约
- 办公室：GET 上游 data 分支 state.json（沿用原页 sha 防缓存拉法，服务端代理兜底 /api/office/state）。
- 行情：复用 FinSight 接口（与 V1 同源同口径）：/api/fusion/status、/api/finance/indices|watchlist|kline|analyze|cyq|sectors|news|picks。标的覆盖 A股(.SS/.SZ)/港股(.HK)/美股。
- 赛跑：modules 数据副本（engine.json）+ 全片静态页内嵌。
- 蜘蛛：本机 :4317 服务内嵌 + 状态由服务端探活；只消费明确标注 DEMO/LIVE 的财经事件投影。
- 财经观测台：统一输出 quotes/filings/news/insights；公开接口当前 DEMO-only，申报单独分类；`app/settings.html` 仅为只读状态占位，不提供认证或写操作。
- 配置安全后续阶段：仅允许白名单非秘密配置（provider enable、source/market、刷新/过期阈值）；公网管理路由默认关闭，不能匿名首次设密；由部署者在私有环境初始化密码后，管理 API 才可在私有部署认证启用。不得通过认证更改 `authorized_scopes` 或把 `local_personal` 提升为 `public`。本阶段不收集/保存 API key；若未来支持，只能由服务端接收并以 0600 私有文件保存，永不回传浏览器。

## 5. 葡语日志翻译层
- 原理：引擎日志是固定句式+变量。前端 translateLog(msg, lang)：按序匹配模板正则 → 输出 zh/en 句式并回填变量（$币名、金额、百分比、计数）。
- 必覆盖句式（以真实日志样本为准）：扫描发现、爬虫汇报、VET 判定（GOOD/WARN/RUG 及理由）、RISK 批准/否决（含短原因）、CHIEF/系统消息、FILLS 工单/成交、情绪 hype、JOURNAL 记账、熔断提示；机器人气泡台词模板同步双语（解析仍按葡语原文，发言用当前语言）。
- 未覆盖：回退原文并加 [原文] 标记，不乱译。decisions 复盘散文：已知条目随仓附译文（decisions.i18n.js 按 token+time 键）。

## 6. 模拟交易台（核心新增）
- 账户：三市场子账户，虚拟初始资金 CNY 1,000,000 / HKD 1,000,000 / USD 100,000（可在设置里重置）。通篇标注 PAPER。
- 下单抽象：OrderGateway 接口 {place(order), cancel(id), list()}；实现 PaperGateway（当前）；BrokerGateway 留口（未接，调用返回「未接入」）。UI 与账本只依赖接口。
- 撮合：市价单按 FinSight 最新报价即时成交；限价单挂单，每次报价轮询（15 秒）检查触发。A股 T+1 与 100 股整数手、港股每手按报价接口（简化为 1 股起、标注模拟规则）、美股 1 股起；费用为模拟参数并在界面明示：A股佣金 0.025%（最低 ¥5）+ 卖出印花 0.05%；港股 0.03%+交易征费约 0.0057%（近似）；美股 0。
- 账本：orders（工单：id/时间/市场/代码/方向/数量/价格/状态/费用）、positions（成本/数量/可卖数量）、fills 流水；服务端持久化 data/paper.db（SQLite）；接口：GET /api/trade/account|positions|orders，POST /api/trade/order|cancel|reset。
- 呈现（办公室内）：交易台分室 = 左报价与 K 线（FinSight 数据）、中下单面板、右持仓与工单表；并在办公室机器人墙加一位「股票交易员 STOCKS」卡（指标=总市值与今日盈亏，台词=最近一笔工单），其工单进办公室日志流呈现（前端合成事件，不改上游数据）。

## 7. 保留清单（不许丢）
办公室：8 人格及全部道具/动画/气泡逻辑、TV 净值 K 线、激光、熔断横幅、SALDO 图、JEV 分析（10 门+轮换+导出 JSON/CSV）、thresholds 代码视图、否决蛛网、filter pills、decisions 数据文件。
数据：state.json 全部字段口径与 V1 已验证数字（赛跑终值 ¥2,746,664/+353.24%/IRR 16.17% 等）不得漂移。

## 8. 验收标准
- 财经观测台和设置页需全站中英双语；公开 API 仅提供 DEMO；设置页无秘密输入和配置写请求；实时 provider 配置/认证不属于此阶段。
- 六个分室真机截图：办公室动画在跑且数据为真（余额/战绩/日志与上游一致）；交易台能完整走通 查价→下单→成交→持仓盈亏变化→卖出 全流程（模拟）；中英切换全站生效且日志为译文；赛跑全片可播；蜘蛛可消费 DEMO 财经事件投影；财经观测台显示 DEMO 标签、四类数据集合和来源时间。
- GitHub 新仓文件与本地哈希逐一相符；README 写明来源与许可状态（grokbot 无 LICENSE、FinSight 为用户自有、spider MIT、财经源逐项核实授权范围）。
